Measured during planning on this tree (emdash 1.3.1, Node 24.17.0): `npx emdash seed .emdash/seed.json --database <tmp>/migrate-check.db --uploads-dir <tmp>/uploads` applies the migrations and the seed; `npx emdash migrate --check --from-config --database <tmp>/migrate-check.db` then exits 0 and prints `Pending: none`; the same check on an empty database file exits 2 (exit codes from src/cli/commands/migrate.ts: 0 success, 1 error, 2 pending, 3 unknown applied). `git diff --exit-code` on an untracked file exits 0, which is why the manifest must be tracked and the gate also runs `git ls-files --error-unmatch`.
`.emdash/migrations.json` is written by every `astro build`; it holds schemaVersion 1, emdashVersion 1.3.1, the 90 migration names with a fingerprint, i18n null and the sqlite executor with url file:./data/emdash.db, with no absolute path and no timestamp, and ends with a newline.
EmDash reads EMDASH_SITE_URL at build time only for image.remotePatterns, and treats an empty value as unset (node_modules/emdash/src/api/public-url.ts getEnvSiteUrl), so a local docker build without the argument behaves as before. The runtime value comes from the container environment set in Dokploy.
