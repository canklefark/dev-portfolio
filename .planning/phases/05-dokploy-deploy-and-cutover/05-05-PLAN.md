```bash
docker run --rm --user OWNER -v portfolio-restore-test:/data node:24-alpine node -e '
const { DatabaseSync } = require("node:sqlite");
const db = new DatabaseSync("/data/emdash.db");
db.exec("PRAGMA foreign_keys = ON");
const q = (sql, ...p) => db.prepare(sql).get(...p).c;
const counts = () => ({ users: q("SELECT count(*) AS c FROM users"), credentials: q("SELECT count(*) AS c FROM credentials"), projects: q("SELECT count(*) AS c FROM ec_projects"), tokens: q("SELECT count(*) AS c FROM _emdash_api_tokens"), setupOptions: q("SELECT count(*) AS c FROM options WHERE name IN (?, ?)", "emdash:setup_complete", "emdash:setup_state") });
console.log("before", counts());
db.prepare("VACUUM INTO ?").run("/data/pre-recovery.db");
console.log("integrity", new DatabaseSync("/data/pre-recovery.db", { readOnly: true }).prepare("PRAGMA integrity_check").get().integrity_check);
db.exec("DELETE FROM users");
db.prepare("DELETE FROM options WHERE name IN (?, ?)").run("emdash:setup_complete", "emdash:setup_state");
console.log("after", counts());
'
```

5. start portfolio-scratch, then at once open https://scratch.zeikcookson.com/_emdash/admin/setup, keep title and tagline, choose Empty site (never Sample content: the content already exists), enter email and name, enroll a passkey for scratch.zeikcookson.com, confirm Projects still lists the production entries, sign out and sign in with that passkey.

Why it is shaped this way: the runtime image has no sqlite3 binary, and a stopped Dokploy app has no container to exec into, so a one-off node:24-alpine container with node:sqlite does the SQL; running as the file owner keeps the -wal, -shm and backup files writable by the app (research Pitfall 10); table names are fixed literals and every value is a bound parameter (CLAUDE.md SQL rule); credentials and API tokens cascade from users only with foreign keys on.
