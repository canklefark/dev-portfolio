<objective>
Move production from the emdash-migration branch to main, put the Cloudflare proxy in front of it, and delete the pipeline code that nothing will run (DEPLOY-01, DEPLOY-03, DEPLOY-04, GUARD-02, GUARD-03). The user deploys by hand: they click Deploy in Dokploy and run the smoke test (user decision 2026-10-27, D-15 superseded). The plan does five things in this order. First, it removes the deploy workflow, the Dokploy API script and its test that plan 05-01 committed, because a deploy workflow on the default branch would start running after every ci run as soon as main is pushed. Second, the user fast-forwards main to emdash-migration and pushes it (a push to main runs ci only), points the Dokploy app at main, clicks Deploy once and runs the smoke test. Third, the user sets SSL/TLS to Full (strict), turns Always Use HTTPS off and proxies the record (D-16), then signs in with their passkey and checks that the OAuth MCP connection still works. Fourth, the executor records what it can see from outside: ci on main, the health route behind the proxy, the smoke test, and parity and the public-JS allowlist behind the proxy. Fifth, a short manual deploy and rollback rule is written into the evidence record.

No separate tracer task is added beyond Task 1: the end-to-end path (Dokploy build, volume, hostname, certificate) is already proven by production (05-03 C1 to C7), and this plan only changes the branch the app builds and what sits in front of it. Task 1's verify still ends with a real request against production.

Purpose: after this plan production builds main, nothing deploys without the owner clicking, the proxy is on and shown to be transparent, and the repo contains no dead deploy code.

Output: the three pipeline files removed and one ci.yml comment corrected on emdash-migration, and 05-EVIDENCE.md with rows C8 to C10 and the Manual deploy and rollback section.
</objective>
