# Phase 3 - UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Contract in one sentence

**This phase changes no pixels.** Every public route renders from EmDash and must match `~/portfolio-baseline/current/dist` (captured at main f4e5470, 2026-10-23) in copy, markup shape, layout, light theme and dark theme. No token, component prop, class name, breakpoint, animation or script is added, removed or retuned. Every value below is **locked to what ships today** and was read from `src/styles/tokens.css`, `src/styles/blocks.css`, the page templates and the baseline HTML, not invented. If an implementation choice would alter a locked value, the implementation changes, not the contract.

Sources: 03-CONTEXT.md (D-01 to D-11 plus the 2026-10-26 amendments), 03-RESEARCH.md (Patterns 1 to 8), DESIGN.md, CLAUDE.md, the baseline HTML.

| ------- | --------------- | --------------------------------------------------------------------- |

| `--s0`  | 16px            | Prose paragraph, list and code-block bottom margin                    |

## Layout and Interaction Contract

**Page structure per route (unchanged):** one 800px column ruled by 1px borders, sticky 56px glass nav, `main#main-content` with the skip link. Home: hero, rule, `Recent Projects` with the newest 3 cards, footer link. Projects index: `All Projects` label then every published card, newest first by `date` (UTC midnight). Project page: back button, category label, h1, status and surface chips, sub, stats grid (`min 9rem`, `data-divider`), prose body. About: h1, role, body, stat cells, contact block, stack table.

**Order and counts:** card order equals the baseline on all 13 cards. Home shows exactly 3. Draft entries never appear in a list or at a URL. A project's category is the single category term label; tags are the tag term labels as `string[]`.

**Tag order (accepted deviation D-01/D-02):** tags render in EmDash term order (sorted by label), not source frontmatter order. Same tags, any order, passes parity. Every other byte of a card must match.

**Interaction states (unchanged, not re-specified):** stage card hover lift, spotlight and underline draw, `READ NOTES →` reveal, `.cta-*` hover, nav link hover and active, theme toggle hover, skip link focus, `u-entry-in` stagger via `--i`, `prefers-reduced-motion` overrides. The `:focus-visible` ring gap noted in DESIGN.md is a known pre-existing item, not part of this phase.

**Routing behavior:** `/projects/{unknown-slug}`, `/projects/{draft-slug}`, `/projects/{database-id}`, `/projects/Wrong-Case`, `/projects/{slug}/extra` and any other unmatched path return a real HTTP 404 that renders the existing `404.astro` (null-body `new Response(null, { status: 404 })`). `404.astro` stays server-rendered, never prerendered.

**JavaScript contract (GUARD-01, ADMIN-01):** zero new JavaScript on any public route.

- The allowlisted baseline stays exactly as recorded in `scripts/script-allowlist.json`: three `is:inline` scripts in `Layout.astro` (theme init, console easter egg, `g h` / `g p` / `g a` keyboard shortcuts), the Nav theme-toggle script, and the 404 timestamp script. These are hashed by `script-inventory.mjs`, so their text must stay byte-identical. The keyboard shortcut routes and the console text stay hardcoded; they are not driven by the menu or settings.
- `toolbar: false` in the emdash integration. `"client"` is never used. No EmDash editor toolbar, admin bundle, `modulepreload` or module tag may reach a public page.
- Public HTML contains no reference to `/_emdash/`. Admin JS exists only under `/_emdash/admin`.
- `check:public-js` fails on any added script, `modulepreload` or `type="module"` tag, proven by the committed fixture self-test (D-11).
