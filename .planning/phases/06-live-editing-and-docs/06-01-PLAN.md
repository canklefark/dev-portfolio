Its sub at planning time: "SvelteKit 2 app backed by SQLite, deployed in Docker on a Dokploy VPS, with async product/FAQ sync to a WordPress REST + ACF backend." The page renders no updated or modified timestamp, and two anonymous GETs returned the same sha1 (0f23a5617458a21237c3604793edf5cb8ba73705 at planning time; Task 2 re-measures, do not reuse this value).
Markers: owner tweak appends " LIVE EDIT CHECK" to sub; agent change appends " AGENT DRAFT CHECK". Plain ASCII so HTML escaping cannot hide them.
EmDash 1.3.1 lifecycle (installed source, read in research): saving a published entry stages a draft and leaves the live columns alone; Publish copies the draft to live; Restore copies an old revision into a NEW draft only (admin toast "The version from {when} is now your draft. Publish when you're ready."), so a second Publish is needed. A valid preview token makes the middleware serve the draft with Cache-Control private, no-store and opt out of route caching; the default token lifetime is 1h; the preview path is built from the collection urlPattern /projects/{slug} (local database and seed), and falls back to /projects/<ULID> if production lacks the pattern, which getProject answers with 404.
MCP (installed emdash MCP server): content_get { collection, id } where id is the ID or slug, returns data, liveData, draftRevisionId and _rev; content_update { collection, id, _rev, data } requires _rev from content_get; with no status, a change to a published item is staged as a draft; an entry open in the admin editor refuses the write with ENTRY_LOCKED unless overrideLock is set, which the agent never sets.
scripts/smoke-test.mjs usage: node scripts/smoke-test.mjs BASE_URL [--attempts N] [--delay-ms MS]; prints smoke-test: PASS when /, /projects/ and the first project page answer 200.
The Cloudflare proxy answered cf-cache-status DYNAMIC on project pages at planning time.
</interfaces>
