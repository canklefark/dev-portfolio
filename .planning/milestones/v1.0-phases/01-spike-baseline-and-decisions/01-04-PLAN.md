Research recipe (01-RESEARCH.md lines 547-628), as observed in the scratch run:

- Persistent CDP session; Node 24 global WebSocket; Chrome started with `--headless=new --remote-debugging-port=9333 --user-data-dir=DIR`.
- `WebAuthn.enable` with enableUI false; `WebAuthn.addVirtualAuthenticator` with options protocol ctap2, transport internal (first) or usb (second; Chrome allows only one internal authenticator per environment), hasResidentKey true, hasUserVerification true, isUserVerified true, automaticPresenceSimulation true; `WebAuthn.setAutomaticPresenceSimulation` with authenticatorId and enabled to choose which authenticator answers.
- Setup wizard at /\_emdash/admin/setup with steps Site, Account and Sign In; button "Create passkey". Second passkey: Settings, Security (/\_emdash/admin/settings/security), "Add Passkey", then a name. Sign-in button: "Sign in with Passkey".
- Credentials table rows carry rpId localhost and a signature counter that advances on each sign-in.
- Media upload: POST /\_emdash/api/media with FormData field "file" and header `X-EmDash-Request: 1` (required for cookie-authenticated writes) returns 201 with item.url `/_emdash/api/media/file/ID.png`; anonymous GET returns 200; `Range: bytes=0-9` returns 206 with `content-range: bytes 0-9/SIZE`.
- Recovery: `sqlite3 data/emdash.db ".backup data/pre-recovery.db"`, `PRAGMA integrity_check` must print ok, then `PRAGMA foreign_keys=ON; DELETE FROM users; DELETE FROM options WHERE name IN ('emdash:setup_complete','emdash:setup_state');`. Deleting users cascades to credentials only with foreign_keys ON. The wizard then reopens and re-prompts for site title and tagline.
