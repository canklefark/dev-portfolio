# Portfolio Intake

This is the source document for building your personal IT portfolio. Write naturally. Short answers are fine, and rough notes are better than polished marketing copy.

The goal is to give enough context to build a site that sounds like you, shows what you are learning and building, and helps technical reviewers understand your direction. If a question does not apply, write "not applicable." If something is private, say so clearly.

## How To Fill This Out

- Answer in plain language.
- Add links, screenshots, resumes, notes, or examples where useful.
- Mark anything sensitive as private.
- Do not worry about formatting. The answers will be turned into site copy later.
- If you are unsure, write what you know and add "not sure yet."

# Builder Notes

Use the completed answers above as the source of truth for the person building the site from this intake. Do not invent background, credentials, preferences, or project outcomes. If an answer is ambiguous, ask before publishing.

## Helper Prompt

Paste the completed intake above this prompt when starting the build session:

```text
You are helping build a one-off Astro portfolio for an IT professional entering a WGU bachelor's program.

Use the completed intake as the source of truth. Synthesize it into:

1. A concise positioning summary for the site.
2. Homepage hero copy and supporting chips/labels.
3. About page prose and structured data.
4. A visual design brief that is distinct from the source portfolio unless the intake independently supports similar choices.
5. A first project inventory with recommended project titles, summaries, statuses, tags, and privacy notes.
6. A learning-notes taxonomy for WGU, IT work, labs, and home projects.
7. Obsidian import rules, including publish marker, draft default, fields to strip, and note-to-Astro content mapping.
8. Open questions that must be answered before implementation.

Do not write polished claims that exceed the evidence in the intake. Mark uncertain content as an open question.
```
